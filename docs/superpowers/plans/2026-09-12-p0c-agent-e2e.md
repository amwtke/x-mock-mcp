# X-Mock-MCP P0C Agent E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 通过统一 MCP 工具让 Codex 与 Claude Code 分别完成后台 Spring Boot 测试、运行时数据回填、固定回放和插件清理。

**Tech Stack:** P0A/B、官方 MCP Go SDK v1.7.0、JSON Schema v0.4.3、YAML v3.0.1、Go testing、Spring Boot/JUnit、真实本地 Codex 与 Claude Code。

- [ ] 场景外层信封定义：

```go
package scenario

import "encoding/json"

type Document struct {
    ID string `json:"id"`
    Version int64 `json:"version"`
    PluginID string `json:"plugin_id"`
    ContractID string `json:"contract_id"`
```

## Task C2: AgentFill 与请求状态机

- [ ] 定义测试 Clock 接口 Now() time.Time、AfterFunc(duration, callback) CancelFunc；testkit 实现 Advance(duration)，用于可重复的截止时间与租约测试。网络 context 取消仍独立生效。
- [ ] 测试同一请求两个并发领取只能成功一个；过期 lease 不可回填；重复相同结果幂等而冲突结果失败；运行 A 的令牌不能回填运行 B。先运行 `go test ./internal/generation -count=1` 观察失败。
- [ ] 定义状态机及原子操作：

```text
pending -> leased -> resolving -> resolved
leased -> pending                 lease 到期且业务 deadline 尚未到达
pending/leased/resolving -> expired/cancelled

Enqueue(ctx, need) -> wait for validated result or cancellation
Next(run_id, owner_token, limit, wait_ms) -> leased requests + lease tokens
Resolve(run_id, request_id, owner_token, lease_token, candidate) -> completion ack
CancelRequest(request_id, reason)
CancelRun(run_id, reason)
```

Next 上限 8 件，wait_ms 范围 0–2000。队列每运行最多 128 个未完成请求、全项目最多 512 个。满队列立即返回 QUEUE_FULL。业务 deadline 不因重领而延长，lease 到期时间取租约与业务 deadline 的较小值。

- [ ] 一个 run 同时只有一个生成 owner。首次 Next 可以领取 owner 并返回随机 owner_token；其他客户端仍可看 status/trace，但没有 token 的 Next 返回 owner 已占用。显式 `takeover=true` 必须附 expected_owner_epoch；成功后递增 epoch、废止旧 token 与旧 lease，并将仍有时间的请求放回 pending。该操作由共享项目访问凭据授权，不能由超时自动触发。
- [ ] 结果处理采用通用 schema 校验 → lease/deadline 二次核对 → per-request resolving 状态 → 将候选结果送给等待中的 AgentFill.Resolve → A5 的 Binding Router 调用右端 Complete → OutcomeObserver 报告最终结果。队列通过 ReportOutcome(request_id, payload, err) 接收该报告；mock_requests_resolve 等待这个完成 ack，而非仅报告候选数据已接收。全局队列锁不能跨 RPC 或等待持有。通用 schema 校验不通过时保持有效 lease，允许在时限内修正；右端 Complete 拒绝旧状态或语义不合法的数据则结束原请求，不生成无界重试循环。
- [ ] completed 结果保留其规范 JSON 摘要与完成 ack 直到运行清理。同一请求的重复相同候选返回已有 ack，不再次调用右端 Complete；不同候选返回 STATE_CONFLICT。若右端进程在 Complete 期间退出，运行失败，不猜测其是否已经应用结果。
- [ ] StrictReplay.Resolve 立即返回 UNMATCHED_REQUEST；AgentFill.Resolve 入队并有界等待。配置 ProviderFill 在 P0 返回 UNSUPPORTED，不能自动读取宿主凭据或调用模型 API。
- [ ] 运行 `go test -race ./internal/generation -count=1`，覆盖取消与 resolve 同时发生、过期 token、takeover、队列满、schema 错误。提交：`feat: add bounded agent request leasing and resolution`。

## Task C5: Spring Boot 流程与自动协作验收

- [ ] 创建 OrdersApplication，使用 SpringApplication.run 启动 Spring Boot。创建 OrderController：

```java
package local.xmock;

import java.util.Map;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class OrderController {
    private final JdbcTemplate jdbc;
    public OrderController(JdbcTemplate jdbc) { this.jdbc = jdbc; }
    @GetMapping("/orders/{id}")
    public Map<String, Object> get(@PathVariable long id) {
        return jdbc.queryForMap(
            "SELECT id, status FROM orders WHERE id = ?", id);
    }
}
```
