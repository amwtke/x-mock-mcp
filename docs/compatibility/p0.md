# P0 兼容性与验收记录

日期：2026-09-12。范围为 MySQL 插件对、Spring Boot 购物 E2E 与 Coding Agent MCP 控制。左端对接应用，右端对接外部依赖；两端分别安装、启用、停用和卸载。没有启动真实数据库或替代 SQL 引擎，没有额外模型 API 配置。

用户明确要求“我没有claude code的账号 只要支持就行 不用E2E区验证”。据此，Claude Code 的账号登录、真实模型生成/E2E 及双真实模型共连不再是 P0 完成条件；保留其真实 CLI 接入检查与多客户端协议测试。下表不把 SDK 客户端测试当成 Claude 模型测试。

## 可复查的测试

运行 `bash scripts/prepare-java.sh` 准备本地依赖，再运行 `bash scripts/verify-p0.sh`。后者记录命令、依赖树、race、集成、vet 与打包日志；任何失败返回非零。

| 检查 | 证据 |
| --- | --- |

| 真实插件生命周期、崩溃隔离、端口冲突、无左端准备 | `integration/plugin_lifecycle_test.go`；`artifacts/p0/integration.log` |

| 真实 HTTP 与 Chromium | `TestShoppingHTTPAndBrowser` |
| AgentFill → 导出 → 三个全新环境 StrictReplay | `TestAgentFlowAndReplay`；每轮 `artifacts/p0/<run_id>/` |
| 双客户端观察/显式换主、旧 token 失效，binding/端点不增加 | 同一个 AgentFlow 集成测试及 generation race 测试 |

| 真实打包与 CLI 固定回放 | `scripts/demo-replay.py`；实际 JSON 输入/输出在 `artifacts/demo/<id>/` |

AgentFlow 每轮保存 Maven 日志、原始 SQL 轨迹、JUnit、Playwright trace 和截图。`business-trace.json` 保留实际业务请求及结果顺序，排除传输 ID、耗时和初态物化造成的状态版本偏移；四轮内容必须一致。回放不会把终态购物车预装到初态，仍需 INSERT 后 UPDATE，记录 5001 的数量依次为 1、2。

业务缺陷测试刷新变更后源码摘要并保持 QA 不变。漏用户过滤由 prepare 发现 SQL 已不在所引用源码；其余三个负例运行真实 HTTP 测试并由业务/状态断言失败。没有用旧摘要错误替代业务缺陷检查。浏览器正例不 mock HTTP，不直接注入 DOM。

## Claude Code 接入检查

在独立配置目录中运行已安装的 Claude Code 2.1.269，无账号、无模型调用。只批准此测试的 `xmock-http` 和 `xmock-stdio` 两个项目 MCP 连接。

首次连接发现工具列表含 `candidate: true` 这种 JSON Schema 布尔简写，Claude 报 `tools fetch failed`。修复后 MCP 控制面的 opaque payload 声明为 JSON object，插件内字段继续由插件 schema 校验；两个真实 CLI 连接均显示 `✔ Connected`。对应失败与成功日志在 `artifacts/p0/hosts/claude/acceptance/mcp-health-before-fix.log`、`mcp-health.log`。标准 SDK 测试也加入此回归检查。

这证明配置、握手和工具发现兼容；不声称 Claude 已执行场景生成或浏览器 E2E。

## MySQL 能力边界

| 能力 | P0 行为 |
| --- | --- |
| 类型 | 有符号 BIGINT、VARCHAR；明确 NULL 和空集列元数据；BIGINT 经 JSON 使用十进制字符串 |
| DDL 输入 | 离线最终 CREATE TABLE，单列主键、组合唯一键、外键、自增；明确拒绝未实现表选项，包括 ENGINE |
| SELECT | 单表显式投影、等值 AND、ORDER BY、常量 LIMIT；源码 SQL AST 与有限参数域匹配 |
| INSERT / UPDATE | 单行插入、固定赋值、同列 BIGINT 累加；约束、影响行数、生成键与状态一致 |
| 事务 | autocommit、BEGIN、COMMIT、ROLLBACK、READ COMMITTED；读己之写与语句级已提交视图；提交时有界冲突检测 |
| 连接 | MySQL native password、本地测试凭据、JDBC/Hikari 系统交互与探活；默认端口 3306，可配置 |
| 生成 | 仅 AgentFill 允许的不可变参考实体；有限租约/截止时间、固定 QA 与 DDL 校验、成功后显式导出 |
| 回放 | 独立环境、固定源码/DDL/插件/场景版本；本地运行依赖仍需提前准备 |

未实现：通用 SQL 引擎、JOIN/聚合/子查询/DELETE、DECIMAL/时间类型/UNSIGNED、运行时 DDL、TLS、长参数流/游标、多结果集、SAVEPOINT、REPEATABLE READ/SERIALIZABLE、完整 InnoDB 锁与死锁语义。事务冲突采用本插件的有界策略，不能替代真实 MySQL 的并发验证。Kafka、ClickHouse、在线插件市场与真实依赖代理均不在 P0。

固定场景的 API 预期用于审查，运行期 API/UI 正确性由真实应用测试断言。右端不会把预期 HTTP JSON 直接回给 JDBC，也不会为了让测试通过自动接受未知请求。
