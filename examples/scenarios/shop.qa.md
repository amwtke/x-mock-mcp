# MySQL 场景资料：QA 填写模板

本模板随 `mysql-mock` 右端策略提供。可以直接写自然语言，无需填写 SQL 或数据库报文。字段含义由 `mysql-mock` 提供的 QA schema 与 guide 定义。该模板对应已实现的 `mock_scenario_prepare` 输入流程。

## 可复制的填写提纲

1. 用例名称、要验证的业务目标。
2. 起始页面、用户角色、是否登录；涉及多用户/多租户时说明身份关系。
3. 初始条件：需要哪些商品/订单、是否上架、库存状态、购物车是否为空。
4. 按顺序写每步“做什么、输入什么、期望看到什么”。
5. 哪些值必须固定，哪些可以让 AI 生成；金额单位、币种、数量与边界条件。
6. 涉及写入时说明后续查询、重复操作、是否扣库存等业务规则。
7. 本次覆盖的异常分支，以及明确不覆盖的分支。
8. 是否接受默认重置：每个独立用例新环境，同一用例各步骤共享状态。

业务规则不明确时标为“需澄清”，不要为了填满模板自行猜测。代码路径、DDL 位置和测试命令由接入方补充，Agent 负责分析实现细节。

## 已填写示例：浏览商品并加入购物车

**目标：** 普通用户能从首页找到商品，查看详情，并将同一商品累计加入自己的购物车。

**角色与起点：** 从首页开始，用户 U1 已登录。另有用户 U2，用于验证购物车隔离。登录方式使用样例工程提供的测试身份配置，本用例不验证真实登录服务。

**初始条件：** 有一件商品 P1 已上架，名为“测试键盘”，价格 99 元人民币，库存 10。U1 和 U2 的购物车都为空。商品 ID、用户 ID 可由 AI 分配，但所有步骤必须保持一致。

| 步骤 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| S1 | 打开首页 | 显示测试键盘，价格 99 元 |
| S2 | 点击测试键盘 | 详情展示同一名称、同一价格、库存 10，可以加入购物车 |
| S3 | 数量选择 1，点击加入购物车 | 提示加入成功；返回的购物车记录有稳定标识 |
| S4 | 打开购物车 | 只有一条测试键盘，数量 1，合计 99 元 |
| S5 | 返回商品详情，再加入 1 件，然后查看购物车 | 仍是一条商品记录，记录标识相同，数量 2，合计 198 元 |
| S6 | 使用 U2 打开购物车 | 购物车为空，不出现 U1 加入的商品 |

**固定业务规则：** 重复加入累计数量，不新建第二条同商品记录。加入购物车不扣库存；本用例结束商品库存仍为 10。金额显示两位小数或等价本地货币格式均可，数值必须准确。

**允许生成：** 内部数字 ID 和不影响本用例的商品附加描述。不得修改商品名称、单价、数量、用户归属、库存和上述预期来配合当前代码输出。

**覆盖范围：** 包含重复加入、再次查询、多用户隔离。下架商品、库存不足、数量非法、登录失败另立用例；事务回滚与并发冲突另由插件/驱动验收覆盖。

**重置：** 每次完整运行从空购物车开始；S1–S6 共用一次运行的状态。

## 接入方与 Agent 补充的技术资料

下表由开发者/接入方提供引用，Agent 据此分析，不要求 QA 手写。

| 资料 | 必须确定的内容 |
| --- | --- |
| 仓库与版本 | 项目目录、commit 或工作区文件摘要；前端和后端分别位于哪里 |
| 表结构 | 最终 DDL，或能离线还原最终结构的迁移文件；业务枚举与金额单位 |
| 应用链路 | 前端入口、API、Controller/Service、Repository/Mapper、DTO、事务注解和配置 |
| 测试配置 | Spring profile、JDK/JDBC 版本、测试身份来源、MySQL 连接配置位置 |
| 启动与验收 | 具名后台任务及参数、浏览器测试入口、预期启动时限 |
| 其他依赖 | 此流程是否访问 Redis、Kafka 或外部登录服务；相应插件或明确的测试配置 |

Agent 输出应包含“步骤 → API → 代码证据 → SQL → 依赖数据/状态 → 断言”的对照表、资料缺口、能力缺口和候选场景包。仅凭这个业务示例不能生成声称适配真实工程的最终 SQL；先读取该工程的代码与 DDL。
